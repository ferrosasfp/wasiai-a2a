### [2026-07-13 09:35] Wave 3 — `vi.mock` factory referenció una clase top-level no hoisteada
- **Error**: en `dashboard.test.ts`, la factory de `vi.mock('../services/reconciliation.js')` referenció `MockReconciliationError`, declarada como `class` a nivel de módulo. Vitest hoistea la llamada `vi.mock` al tope del archivo, así que la clase aún era `undefined` al momento del mock → toda la suite del archivo falló al colectar (`PASS (0) FAIL (0)` + "There was an error when mocking a module").
- **Causa raíz**: `vi.mock` es hoisted; cualquier símbolo que su factory use debe estar disponible ANTES del hoist. Una `class`/`const` normal a nivel de módulo NO se hoistea junto con el mock.
- **Fix**: envolver la clase en `vi.hoisted(() => { class ReconciliationError extends Error {…}; return ReconciliationError; })` y usar esa referencia tanto en la factory como en los `mockRejectedValue(new MockReconciliationError(...))` del test.
- **Aplicar en**: cualquier test que necesite exponer una clase/valor propio DENTRO de una factory de `vi.mock` (error classes, fixtures). Regla: todo símbolo consumido por una factory `vi.mock` va en `vi.hoisted` (o se declara dentro de la propia factory). Los `vi.fn()` de este repo ya siguen el patrón (`vi.hoisted(() => vi.fn())`).
